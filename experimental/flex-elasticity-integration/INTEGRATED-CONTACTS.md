# Flex elasticity with shared constrained movement

`MJ.Data.Constrained.Flex` combines compiled flex elasticity, collision geometry,
contact Jacobians, rigid mass coupling, PGS/CG/Newton response and Euler on one
owned `Simulation`. It loads MJB data and accepts state, activation, controls
and applied forces. No contacts, Jacobians or solved forces come from C.

The latest validated element5 snapshot supports primitive, mesh and heightfield geoms,
flex-vertex and non-interpolated flex-element endpoints. Primitive rigid pairs
are generated by the rigid scene; all contacts are stably merged by body/flex
pair order before assembly. Membranes support stretch and bending, tetrahedra
continuum elasticity, and edges spring/damper forces. Free, slide and shared
articulated coordinates use the same full mass/response path. Contact material
mixing, condim 1/3/4/6 and pyramidal/elliptic cones use the existing solver code.
Existing constrained restrictions apply, including disabled warmstart/islands.
Self/cross-flex response and tetrahedral internal contacts, also combined with
elastic forces, pass validation and release on central r10. Interpolated flexes remain rejected. The newer SDF/flex extension has its
separate r12 receipt described below. Mesh/heightfield assets are copied once by the
existing central loader and released by the flex scene; no per-step allocation
is added.

`Flex_Elasticity.Force_Model` owns compiled elastic metadata separately from
state. It must be evaluated on the Simulation created from that same Model;
body/DOF counts are checked, while full topology identity remains a caller
obligation. `Create` temporarily detaches flex arrays while constructing the
rigid subengine and restores every array/name/size/capacity field before return.
The original Model can then be freed. Repeated Evaluate reconstructs the base
passive contribution before adding flex forces, preventing double accumulation.

The flex geometry adapter receives global geom poses from the shared constrained
pose generator, preserving quaternion composition and compiled same-frame
shortcuts. Contact response receives explicit body endpoints independently of
optional geom IDs (`-1` on a flex side); surface velocity applies only where an
actual geom exists. Public flex contact diagnostics retain geom/flex/vertex IDs.
Legacy rigid-only `Full_Contact.Geoms` inside the response buffer is not exposed
as the identity of a flex contact.

Validation closure `/var/tmp/sparkling-recovery-flex-contact3-20261003` passes
54/54 samples across 27 models at 100 steps. Checks include counts, passive
forces, free and constrained accelerations, generalized constraint force and
complete state, at absolute/relative tolerance 2e-9. Cases include pinned/free/
shared state, two planes, tilted planes, margins/gaps, muscle activation,
frictionloss/limits, contact/constraint disable flags and all supported solver/
cone combinations. The probe also checks endpoint rejection atomicity, model
restoration, repeated evaluation and state rejection. The comparison harness
sets a 128 MiB stack for the current static workspaces.

Complete child flow closes 33 checks (19 warnings); updated flex-state flow
closes 62 (8 warnings). These are initialization/dependency results, not a full
runtime-safety or functional proof. Scalar elasticity kernels retain their
separate 145-check whole-unit proof; the reusable force refactor passes the
75-case contact-free corpus and 83 flow checks. Frozen hashes and individual
scope receipts are in `evidence/20261003-integrated-contact`. Added contracts
and later source/dependency edits require fresh proof/build receipts. No
integrated performance-parity claim is made from these numerical checks.

Build with `tests/build_constrained.py --out NEW_DIRECTORY`, then run
`tests/compare_constrained.py --binary NEW_DIRECTORY/build/validation/bin/flex_constrained_probe
--out NEW_RESULTS --samples 2 --steps 100`. Use `tests/prove_constrained.py
--build NEW_DIRECTORY --out NEW_PROOFS` for child/state flow; Evaluate, Step and
whole-unit proof scopes are explicit bounded diagnostics. `--resume` refreshes
only this entry in a previously copied closure and retains its dependency
hashes. Never treat an unsuccessful build as evidence from a copied old binary.

## Element extension and central integration

The current child also produces primitive/element contacts and invokes the rigid
scene for rigid/rigid pairs. Element1/2/3 receipts use the recorded
`integration/constrained-weighted-endpoints.patch` in isolated snapshots of
central r7. The central owner has since applied that API and added atomic/frame
postconditions. Element4 verifies the fresh central r10 composition, with
266 shared source hashes unchanged and no isolated central patch.
The C reference remains unmodified.

Element endpoints retain up to four ordered positive body weights. The producer
implements C inverse-distance weights and rounded ordered normalization, without
claiming exact real or floating-point sum equal to one. The response retains
common ancestors and duplicate bodies during accumulation, and applies linear
weighted inverse body masses in regularization. Single vertex endpoints continue
to use the original body-pair path.

Validation and release element2 both pass 138/138 samples at 100 steps on
identical 309-file source maps, with identical numerical error records. The
original 54 vertex cases are joined by 84 element cases, including shared
ancestors, repeated bodies and simultaneous rigid/rigid contacts. Additional
Jacobian, aref and regularization comparisons use the same 2e-9 tolerance.
All new fixtures require an actual element contact. Child flow closes 57 checks
and state flow 66; complete safety and functional proofs remain pending.
Element3 validation passes 162/162 samples at 100 steps, adding 24 self/cross/
internal samples with no passive elastic forces. Self pairs follow all
inter-object pairs, and internal tetrahedron weights omit the last opposite
vertex match. Element3 release and fresh flow remain pending. The scalar
inverse-distance/ordered-normalization unit closes 93 checks, including exact
floating-point component relations and failure preservation. This does not
establish exact real normalization or the complete contact producer's proof.
Element4 validation and release both pass 186/186 at 100 steps, with identical
323-file source maps and numerical error records. It adds 24 self/cross/internal
cases with actual elastic passive forces and renews child/state/elasticity flow
at 57/66/83 checks, zero open (26/8/90 warnings retained). Full safety and
functional proofs remain open. Mesh/heightfield extension results will be
recorded separately. Element5 extends this to 234/234 samples at 100 steps in
both profiles, with identical source maps and numerical error records. The 48
asset samples cover edges, triangles and tetrahedra, cube and ring meshes,
heightfield grids, nonzero asset offsets, pyramidal3 and elliptic6. The initial
32/48 asset failure is retained: forces/state passed but row order differed.
Reproducing C's stable post-midphase geom/element/vertex sort closes J/aref as
well, without weakening the checks. Fresh child/state/elasticity flow closes
57/74/83 checks, zero open (26/9/90 warnings). A separate 48-sample asset corpus
with midphase disabled also passes in both profiles with identical error
records, exercising the branch that preserves linear collision order.

`tests/benchmark_constrained.py` prepares comparable complete trajectories from
the exact MJB/input corpus, alternates baseline Ada/candidate Ada/native C,
excludes reset/I/O and one warmup trajectory, checks final state, and retains
per-block samples, source/binary/reference hashes and timing distributions.
The driver has not yet been exercised; no flex performance conclusion follows
from its presence. Use a coordinated quiet window before interpreting timings.
Receipts are in
`evidence/20261003-element-contact`. Earlier flex4 validation/release both pass
54/54 with identical error records and 258 shared hashes matching central r7;
its child/state/elastic flow scopes close 33/62/83 checks respectively.

This is distinct from the no-BVH linear path. Initial failed fixtures and
comparisons remain in the evidence, and the official C source/library remain
unmodified. The separate known native mesh/SDF abort is still a baseline failure.
