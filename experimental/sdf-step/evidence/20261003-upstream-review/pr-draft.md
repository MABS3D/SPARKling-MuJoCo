Mesh-SDF collisions can return more contacts than `sdf_initpoints`, because the narrow phase samples each mesh face. The driver nevertheless uses `sdf_initpoints` as the per-pair output capacity. A valid tetrahedron against a mesh-derived SDF with `sdf_initpoints="1"` generates two contacts, exceeds the reserved pair buffer, and aborts in `collisionTask`.

Use `mjMAXCONPAIR` for mesh-SDF pairs, matching the existing candidate bound in `mjc_MeshSDF`. Other SDF pair types retain their existing capacity. This changes allocation only; the narrow-phase contact algorithm is unchanged.

The added regression invokes the registered collider into a full buffer, checks both geom argument orders against `mj_maxContact`, then runs `mj_forward` with and without a worker pool for 1, 4, 40 and 80 initial points. It fails before the fix and passes afterward. The full collision-driver test target passes 14/14 tests in double and single precision. An independent 80-run matrix passes in each precision, including reversed geom order, primitive/SDF and SDF/SDF controls, and 0/2 worker threads. All 148 runs that already succeeded before the fix keep identical contact output. A separate 33-pair model also passes with and without workers. Validation used GCC 13.3.0 on Linux x86_64; the full MuJoCo suite and other platforms have not been run.
